# Тестовий прогін: `.claude/commands/add-tests.md`

**Як рендериться реальна slash-команда:** Claude Code підставляє
`$ARGUMENTS` у тіло файлу командою користувача (`/add-tests <шлях>`).
Щоб перевірити команду без інтерактивного UI, тіло файлу відрендерено
буквальною підстановкою `$ARGUMENTS` → `app/src/quote.ts` (`sed`), рамка
frontmatter прибрана — саме так, як це зробив би сам Claude Code — і
результат віддано окремому підагенту як реальний запит.

## Рендерений промпт (те, що фактично побачив агент)

```
Ціль файлу/модуля: app/src/quote.ts

Якщо `app/src/quote.ts` порожній — попроси користувача вказати файл, не вгадуй.

## Роль

Senior-розробник, що пише production-код з тестами і виправляє дефекти,
які тести виявляють — а не підлаштовує тести під баговану поведінку.

## Мета

Довести test coverage вказаного файлу до повністю зеленого стану,
**виправивши причину дефекту в реалізації** (якщо тест його виявить), і
додати тести на крайові випадки, яких зараз бракує.

## Контекст

- Ціль: `app/src/quote.ts` і його файл тестів (знайди відповідний `*.test.*`/
  `*.spec.*` поруч або за конвенцією проєкту).
- Перед написанням нових тестів прочитай наявні — не дублюй те, що вже
  покрито.

## Обмеження

- Diff обмежений цільовим файлом і його файлом тестів — не чіпай
  конфігурацію, залежності, чи файли поза цим scope.
- Публічні сигнатури функцій/класів незмінні, якщо задача прямо не
  вимагає зміни контракту.
- Наявні тести не можна видаляти, скіпати (`.skip`/`xit`) чи послаблювати
  (змінювати очікуване значення під поточну баговану поведінку) — вони
  мають пройти через виправлення реалізації, а не через зміну очікувань.
- Заборонено досягати «зелених тестів» через `.skip`/`.only`, глушіння
  помилок, `@ts-ignore`/`any`/еквіваленти в іншій мові.

## Acceptance criteria

- [ ] Якщо є дефект, який тест виявляє — він виправлений у реалізації, не
      в тесті.
- [ ] Додано щонайменше 3 нові тести на крайові випадки, яких не було.
- [ ] Команда тестів проєкту (знайди її в `package.json`/README/CI-конфігу)
      — 0 failing.
- [ ] Typecheck/lint проєкту (якщо є) — без помилок.
- [ ] Жоден наявний тест-кейс не видалений — якщо структура змінилась, дай
      список «до/після».

## Формат відповіді

1. Список знайдених дефектів (якщо є): `файл:рядок | вхід | наслідок`.
2. Diff.
3. Коротке пояснення причини дефекту й підходу до фіксу.
4. Підсумок запуску тестів: passed/failed до і після.

## Stop

Коли тести зелені й жоден наявний тест не постраждав — зупинись. Не
додавай нових публічних функцій чи фіч поза межами виправлення дефекту.
```

### Звіт

**1. Знайдені дефекти:** жодних. Прогнав `npm test` (25 тестів у `app/src/quote.test.ts`) і `npm run typecheck` до будь-яких змін — обидва вже були зелені/чисті. Ручна трасировка `distributeRemainderCents`/`splitInstallments` на всіх крайових значеннях, включно з тими, що коментарі в тестах позначали як "FAILS зараз", підтвердила: сума платежів коректно дорівнює `totalCents` (залишки коректно розподіляються). Отже дефект, згаданий в AGENTS.md/docstring-коментарях, у поточному стані файлу вже виправлений раніше (`prompts/debug-quote.md` за коментарями в коді) — фіксувати нічого.

**2. Diff** (лише `app/src/quote.test.ts`, +22 рядки, нічого не видалено/змінено в наявних тестах):
- `estimateTotalCents`: додано тест "нульова ставка дає 0 незалежно від годин і знижки".
