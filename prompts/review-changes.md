# Рев'ю накопиченого дифу перед PR

## Роль

Незалежний рев'юер, що бачить діф вперше — без контексту про те, чому ці
зміни робились, і без бажання «захистити» власну попередню роботу.

## Мета

Знайти в накопиченому дифі дефекти коректності, розбіжності між кодом,
тестами й документацією — перш ніж це піде в PR.

## Контекст

- Діф: `git diff <hash-до-Task-A>..HEAD` (увесь `app/`, включно з
  `quote.ts`, `quote.test.ts`, `README.md`).
- Тести: `cd app && npm test`; typecheck: `cd app && npm run typecheck`.
- Домен: кошториси, усі суми — цілі центи.

## Обмеження

- НЕ переписуй код і не пропонуй рефакторинг «на смак» — лише дефекти й
  розбіжності.
- Явно звір **три джерела** між собою: реалізацію (`quote.ts`), тести
  (`quote.test.ts`) і документацію (`README.md`) — і скажи, чи вони
  узгоджені.
- Максимум 7 знахідок, відсортованих за серйозністю.

## Acceptance criteria

- [ ] Кожна знахідка: файл:рядок, у чому проблема, конкретний вхід (якщо
      застосовно), що саме зламається чи розійдеться.
- [ ] Явно перевірено крайові випадки: 0, від'ємні значення, дробові
      `parts`/`hours`, дуже великі числа (переповнення `Number`).
- [ ] Явно сказано, чи README досі точно описує поведінку коду (є ризик, що
      документація «застаріє» після наступного фіксу).
- [ ] Якщо дефектів немає — так і написано, без вигаданих зауважень.

## Формат відповіді

Список знахідок:
`СЕРЙОЗНІСТЬ | файл:рядок | проблема | вхід (якщо є) | наслідок`

## Stop

Після списку знахідок зупинись. Виправлення — окремим запитом (інший
промпт з cookbook).

## Нотатки із запуску (доказ, що промпт працював)

**Задача:** рев'ю кумулятивного дифу цього репозиторію (`git diff
08ded3c..HEAD -- app/`) після прогонів `add-tests.md`, `debug-quote.md`,
`refactor-quote.md`, `write-docs.md` — тобто саме той код, що піде в PR.

**Результат запуску — рев'юер знайшов реальні розбіжності, яких попередні
промпти не покрили:**

1. ~~**HIGH**~~ **[ІСТОРИЧНЕ, закрито]** — `app/src/quote.ts` (валідація в
   `splitInstallments` перевіряла лише `Number.isInteger(parts) && parts >
   0`, без верхньої межі) розходилась із `README.md`, який стверджував, що
   функція «більше не падає з незрозумілим RangeError». Для
   `parts = 4294967296` це все ще кидало нативний
   `RangeError: Invalid array length`, а для `parts = 4294967295`
   (формально валідний за тодішньою перевіркою) процес падав з
   `FATAL ERROR: JavaScript heap out of memory`. **Закрито в тому ж циклі
   Task A** через `MAX_INSTALLMENT_PARTS = 100_000` (див. `app/src/quote.ts`,
   коміт після цього рев'ю) — тепер `parts` понад межу кидає явну помилку.
2. ~~**MEDIUM**~~ **[ІСТОРИЧНЕ, закрито]** — README жирним стверджував
   «сума елементів масиву завжди точно дорівнює totalCents», але
   `totalCents` ніде не валідувався на цілочисельність.
   `splitInstallments(1000.7, 3)` → `[334, 334, 333]`, сума
   `1001 ≠ 1000.7` — мовчки, без помилки. **Закрито**: `splitInstallments`
   тепер кидає явну помилку для нецілого `totalCents`
   (`Number.isInteger(totalCents)` перевірка на початку функції).
3. **LOW — усе ще відкрито.** README детально описує неваліджований
   `discountPercent`, але не згадує, що `hours`/`rateCents` так само
   неваліджовані для від'ємних значень
   (`estimateTotalCents({hours: -5, rateCents: 5000})` → `-25000` без
   попередження), і це не покрито жодним тестом.

**Що з цим зробили:** відповідно до Stop-правила цього промпту (список
знахідок, не фікс), у межах *цього конкретного запуску* нічого не
виправлено — фікс знахідок 1 і 2 стався окремим кроком одразу після
(правильний порядок дій за правилами бібліотеки: рев'ю → окремий фікс).
Знахідка 3 (`estimateTotalCents` не валідує від'ємні `hours`/`rateCents`)
досі відкрита — якщо це піде далі в продакшн, вартує ще однієї ітерації
`debug-quote.md`-подібного промпту.

**Чому це окремий промпт, а не `review-pr.md`:** `review-pr.md` — наданий
приклад-планка, що не рахується в бібліотеку (правило `prompts/README.md`);
цей промпт додає власну вимогу — звірку трьох джерел (код/тести/документація)
одне з одним, якої немає в прикладі.
