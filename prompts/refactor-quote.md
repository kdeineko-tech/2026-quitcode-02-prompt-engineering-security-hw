# Рефакторинг без зміни поведінки

## Роль

Senior TypeScript-розробник, що покращує читабельність і повторне
використання коду, не змінюючи жодної спостережуваної поведінки.

## Мета

Винести логіку розподілу залишку центів у `splitInstallments` в окрему
чисту, названу функцію — щоб її можна було читати й тестувати незалежно —
не змінюючи поведінку жодної публічної функції.

## Контекст

- Файл: `app/src/quote.ts`, функція `splitInstallments` — усередині є
  ~5 рядків логіки «базове значення + розподіл залишку по одному центу», яка
  зараз вбудована прямо в тіло функції.
- Тести: `app/src/quote.test.ts` — усі мають лишитись зеленими без жодної
  зміни (це чистий рефакторинг, не виправлення дефекту).

## Обмеження

- Це **рефакторинг, не фікс**: жодна публічна функція не повинна змінити
  поведінку для жодного входу, який вже покритий тестами.
- Diff обмежений `app/src/quote.ts`. `app/src/quote.test.ts` **не чіпати**
  взагалі (жодних змін) — якщо рефакторинг вимагає зміни тестів, це ознака,
  що це вже не чистий рефакторинг, і треба зупинитись і повідомити.
- Публічний експортований API (`estimateTotalCents`, `splitInstallments`,
  `formatMoney`, `QuoteInput`) незмінний: ті самі імена, сигнатури, поведінка.
- Нову внутрішню функцію можна залишити неекспортованою (private), якщо вона
  не потрібна ззовні.

## Acceptance criteria

- [ ] Логіка розподілу залишку винесена в окрему функцію з описовою назвою
      (не `helper1` тощо) і JSDoc-коментарем, що саме вона робить.
- [ ] `splitInstallments` стає тонкою обгорткою: валідація → виклик нової
      функції → повернення результату.
- [ ] `app/src/quote.test.ts` не змінено **жодним чином** (перевір діфом,
      що файл байт-в-байт ідентичний).
- [ ] `cd app && npm test` — усі тести, що були зеленими, лишаються зеленими,
      без жодної зміни очікувань.
- [ ] `cd app && npm run typecheck` — без помилок.

## Формат відповіді

1. Diff (лише `app/src/quote.ts`).
2. Одне речення, чому нова структура читабельніша/повторновживаніша.
3. Підтвердження: `git diff --stat` показує 0 змін у `quote.test.ts`.
4. Результат тестів до/після (мають бути ідентичні числа).

## Stop

Як тільки тести незмінно зелені й `quote.test.ts` не зачеплено — зупинись.
Не рефактор форматування деінде у файлі, яке не стосується цієї функції.

## Нотатки із запуску (доказ, що промпт працював)

**До:** `app/src/quote.ts`, `splitInstallments` — логіка розподілу залишку
(`base`, `remainder`, цикл `for`) вбудована прямо в тіло функції поруч із
валідацією `parts`.

**Рефакторинг:** винесено чисту функцію
`distributeRemainder(base: number, remainder: number, parts: number): number[]`
з JSDoc, що описує контракт («повертає масив довжиною `parts`, де перші
`|remainder|` елементів відрізняються від `base` на ±1»).
`splitInstallments` тепер: валідація `parts` → обчислення `base`/`remainder`
→ `return distributeRemainder(base, remainder, parts)`.

**Перевірка, що це справді рефакторинг, а не прихований фікс:**
`app/src/quote.test.ts` лишився без жодної зміни
(`git diff --stat` показує 0 insertions/deletions для цього файлу).

**Після:** `cd app && npm test` — **23 passed, 0 failing** (те саме число,
що й до рефакторингу). `npm run typecheck` — без помилок.
