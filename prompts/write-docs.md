# Документація модуля

## Роль

Technical writer з бекграundом TypeScript-розробника: пишеш документацію,
яку читає інший розробник команди, а не маркетинг-текст.

## Мета

Створити `app/README.md`, що документує публічний API `app/src/quote.ts`:
що робить кожна функція, приклад виклику, і — обов'язково — які вхідні дані
кидають помилку чи мають нестандартну поведінку.

## Контекст

- Файл: `app/src/quote.ts` — три експортовані функції
  (`estimateTotalCents`, `splitInstallments`, `formatMoney`) + тип
  `QuoteInput`.
- Джерело істини для крайових випадків — `app/src/quote.test.ts` (не вигадуй
  поведінку, якої немає в тестах чи коді).
- Аудиторія: розробник команди, який підключає цей модуль у свій код і не
  хоче читати реалізацію, щоб дізнатись, що станеться при `parts = 0`.

## Обмеження

- Тільки читання коду — жодних змін у `app/src/*`.
- Не документуй внутрішню приватну функцію (`distributeRemainderCents`),
  якщо вона не експортована — README про публічний API.
- Без маркетингового тону («потужний», «сучасний») — тільки факти й приклади.
- Кожен приклад коду має бути **виконуваним і коректним** (реальні значення
  з реальним результатом, не псевдокод).

## Acceptance criteria

- [ ] Кожна з 3 публічних функцій має: опис, сигнатуру, приклад виклику з
      конкретними значеннями і реальним результатом.
- [ ] Явно задокументовано, що `splitInstallments` кидає помилку для
      нецілого чи невід'ємного `parts` (з прикладом, який саме вхід ламається).
- [ ] Явно задокументовано, що всі суми — цілі центи, і чому (уникнення
      float-похибок), з одним прикладом float-проблеми, якої це уникає.
- [ ] Приклади в README перевірено — фактично запущено відповідний код і
      підтверджено результат (не вигадано).
- [ ] Немає розбіжностей із поведінкою в `quote.test.ts` (документація не
      суперечить тестам).

## Формат відповіді

Готовий вміст `app/README.md` (Markdown): короткий вступ, розділ на кожну
функцію, розділ «Обмеження і крайові випадки».

## Stop

Після написання `app/README.md` і перевірки прикладів — зупинись. Не
документуй внутрішню реалізацію рядок-у-рядок.

## Нотатки із запуску (доказ, що промпт працював)

**Запущено проти:** `app/src/quote.ts` (з валідацією `parts` і
`distributeRemainderCents`, після Task A debug/refactor прогонів).

**Результат:** створено `app/README.md` з розділами на всі 3 функції,
прикладами (`estimateTotalCents({hours:10, rateCents:5000, discountPercent:10})
→ 45000`, `splitInstallments(100, 3) → [34, 33, 33]`,
`formatMoney(123450) → "$1,234.50"`) і явним розділом про помилку
`parts must be a positive integer` з прикладом `splitInstallments(100, 0)`.

**Перевірка прикладів:** значення в README звірено з реальним запуском
`node`/`vitest`, а не вигадані — усі відповідають тестам у
`quote.test.ts` і фактичному виводу функцій.
